# GPT Image 防碎图工作流

把“碎图”当作一组不同故障，而不是一个可由万能负面词解决的问题。目标是降低触发概率、尽早拒收坏图，并从干净状态恢复；模型侧纹理噪声只能缓解，不能承诺根治。

## 工作原则

1. 保留用户的主题、风格和用途，不擅自删掉核心创意。
2. 优先建立几何和空间，再分配细节；细节不应平均铺满整张图。
3. 使用少量、与当前风险直接相关的排除项。不要粘贴 Stable Diffusion 式超长负面词表。
4. 生成后必须看图验收。提示词看起来正确不代表输出合格。
5. 不把已经出现全局碎纹、蜂窝或网格伪影的图片反复递归编辑；回到最后一张干净图或重新生成。

## 第一步：判断故障类型

生成前做风险预检；已有失败图片时先按下列类型归类。需要更细的症状表和恢复动作时，读取 [references/diagnosis-and-recovery.md](references/diagnosis-and-recovery.md)。

- **传输或中间态错误**：文件截断、解码失败，或 API 把流式 `partial_image` 当成最终图。
- **全局纹理破碎**：蜂窝、棋盘格、斜网格、彩色碎屑、脏噪点、重复微纹理、过度锐化。
- **版式破碎**：用户要单幅画面，却得到拼贴、分屏、多格漫画、角色表、信息图或随机边框。
- **空间或材质破碎**：背景不连续、物体粘连、漂浮碎片、边界融化、透视或光源互相冲突。
- **解剖或动作破碎**：额外/缺失肢体、左右互换、人物融合、接触点断开、遮挡关系不可能。
- **编辑或上下文漂移**：未编辑区域改变、旧图元素幽灵般残留、连续迭代越来越脏。

无法确定类型时，不要猜模型内部原因。先检查原始成品文件和实际发送给图像模型的最终提示，再分别测试一个简化提示和一个新会话。

## 第二步：建立连贯性规格

在调用图像工具前，把用户请求规范化为简洁、可扫描的视觉规格。复杂请求使用短标签或换行，按下面的顺序组织：

```text
用途：<成品将用于哪里>
画面承诺：一张完整连续的画面；<一个场景、同一时刻、同一摄影机视角>
场景：<地点与前景/中景/背景>
主体：<精确数量、身份、外观；一个主要焦点>
空间关系：<各主体位置、相对尺度、前后遮挡、接触点>
动作：<每个主体一个清晰动作；视线与手脚关系>
镜头与构图：<景别、视角、透视、完整入镜范围、留白>
材质与细节层级：<焦点高细节，次要区域中等，背景受控>
光照：<一个主光源、方向、色温、阴影>
风格/媒介：<一个主媒介和相容的风格族>
必须保持：<编辑或参考图中的不变量>
排除：<只列与当前风险直接相关的 3–8 项>
```

只保留有帮助的字段。用户提示已经具体时，仅重排和消歧，不增加人物、道具、品牌、故事情节或未经要求的左右布局。

需要可复制模板时，读取 [references/prompt-patterns.md](references/prompt-patterns.md)。

## 第三步：应用防碎约束

### 连续画面

除非用户明确要求拼贴、分镜或角色表，否则建立以下承诺：

```text
一张完整、连续的单场景画面；同一空间、同一时刻、同一摄影机视角。
没有拼贴、分屏、多面板、角色表、接触表、随机边框或互不连通的小场景。
```

如果用户要求多个独立成品，先列出每张图的独立提示，再逐张调用图像工具。不要把“几个方案”压进一张画布。

### 复杂度预算

- 指定唯一主焦点、一个主动作和一个主光源。
- 让焦点区域承担精细纹理；次要区域减少微细节；背景使用较大、连续、安静的形状。
- 优先使用“连续表面、清晰材质边界、轮廓分离、受控细节密度、统一透视和色温”等正向结构语言。
- 用户未明确要求时，削减 `hyper-detailed everywhere`、`maximalist`、`countless tiny details`、`overloaded` 等全局密度词。
- 避免同时堆叠多种透明、发光、反射、雾化、颗粒和裂纹材质；保留真正服务主题的部分。
- 不把“提示很长”本身判为问题。判断是否存在对象关系不明、互相冲突或超过画面承载能力的细节。

### 人物、动物与复杂动作

- 写出精确主体数量；每个主体只承担一个可读动作。
- 说明全身/半身、脚是否入镜、人物自身的左/右、哪只手接触哪个物体、哪只脚承重。
- 写清前后关系、遮挡和接触点。多主体优先错开轮廓，避免身体大面积重叠。
- 需要复杂姿势时，使用轮廓清楚的姿势参考，并把“人物自身左右”而非“画面左右”写明。
- 对精灵帧、转面或动作序列逐帧生成，再用确定性工具拼接；不要要求模型一次完成整张 sheet。

### 参考图与编辑

- 只使用完成任务所需、且没有现成碎纹的干净参考图。
- 按 `Image 1`、`Image 2` 编号，每张图只声明清楚的职责：底图、主体、姿势、服装、风格或背景。
- 明确“从哪张图取什么、放到哪里、哪些内容绝不复制”。
- 合成时统一尺度、透视、光照方向、色温、遮挡和接触阴影。
- 每轮只做一个主要改动，并重申身份、几何、镜头、背景和未编辑区域等不变量。
- 每次成功编辑后保存干净检查点。局部 mask 是软约束，仍需检查选择区外是否漂移。

## 第四步：选择生成路径

### 内置图像工具

- 使用当前环境规定的内置图像生成/编辑流程，不臆造它没有暴露的 `quality`、`size`、seed 或 CFG 参数。
- 多个独立成品使用独立工具调用。
- 编辑本地图片前，先让图片进入可见上下文并检查原图。
- 生成后检查实际成品，不用模糊预览图代替验收。

### `gpt-image-2` API

- 排障时先用常用、非实验尺寸验证构图，例如 `1024x1024`、`1536x1024` 或 `1024x1536`。
- 超过 `2560x1440` 总像素的输出更易波动；不要从实验性超高分辨率开始定位问题。
- `low` 用于草稿；人物、密集细节、身份敏感编辑或最终资产比较 `medium`/`high`，但不要声称高质量能修复所有结构错误。
- 对 `gpt-image-2` 省略 `input_fidelity`；模型自动按高保真处理输入图。
- 流式工作流只把 `completed`/最终事件保存为成品；`partial_image` 仅用于预览。
- 记录并检查 `revised_prompt`。若它引入了多场景、面板、海报或未要求的对象，先修正最终提示再重试。
- 生产流程可锁定已验证的模型快照以做回归，但不要把快照误称为固定 seed 或逐像素确定性。

## 第五步：生成后验收

检查原始输出，必要时放大到 100%–200%。至少验证：

1. **整体**：是否是一张连续画面；主体数量、主焦点和故事时刻是否正确。
2. **空间**：地平线、透视、前中后景、遮挡、接触点、阴影和光源是否一致。
3. **轮廓与解剖**：头、躯干、肢体、手脚、尾巴、翅膀等是否数量正确且连续连接。
4. **纹理**：天空、皮肤、雾、水、毛发、树叶和暗部是否出现蜂窝、棋盘格、重复碎块或脏噪点。
5. **边界**：是否有随机接缝、边框、局部贴片、融合材质或漂浮碎片。
6. **编辑不变量**：选择区外、人物身份、镜头、背景和未要求内容是否保持。

把违反主体数量、连续画面、明显解剖错误、全局碎纹或编辑不变量的结果判为失败，不要仅因色彩漂亮而接受。

## 第六步：按故障恢复

每次只改变一个主要变量，避免无法判断哪项起效。

1. **孤立、随机的小错误**：保持提示不变重试一次；若仍相同，进入下一步。
2. **布局、空间或解剖错误**：补足数量、位置、遮挡、接触和镜头关系；降低主体重叠后重新生成。
3. **全局碎纹或材质融合**：减少主体、微纹理和复合材质；改为受控细节层级，从头生成而不是继续编辑坏图。
4. **连续迭代恶化或意外锁成拼贴/信息图**：回到干净检查点；必要时用压缩后的完整提示在新会话重新开始。新会话是经验性兜底，不是官方保证。
5. **局部编辑大范围漂移**：回退检查点、缩小单次改动；小缺陷优先用确定性编辑工具修补。
6. **连续多次出现同一全局噪声**：停止堆叠提示词，说明可能是模型侧限制，并保留干净提示和失败样本用于回归测试。

## 输出约定

如果用户要生成或编辑图片：

- 内部完成风险预检和提示规范化，不必把全部分析展示给用户。
- 调用图像工具，检查输出；失败时按恢复阶梯做有限重试。
- 最终给出选中的图片、实际使用的最终提示、验收结论，以及工作区资产的完整保存路径（若有）。
- 如果仍存在模型侧碎纹，明确说明残留和已尝试的步骤，不承诺已根治。

如果用户只要优化提示词：

- 输出一份可直接复制的最终提示。
- 另用几行列出识别到的高风险点和采用的防碎处理。

用户询问依据或当前模型能力时，再读取 [references/evidence.md](references/evidence.md)；不要在普通生成请求中加载研究笔记。
